\subsection{Lý do lựa chọn kiến trúc và hồ sơ quyết định kiến trúc}\label{appendix:architecture-rationale}

Các quyết định kiến trúc của IRMS được đặt trên ba cơ sở: bối cảnh vận hành của nhà hàng, yêu cầu chức năng theo từng miền nghiệp vụ và yêu cầu phi chức năng ở mức toàn dự án. Kiến trúc chủ đạo là \textbf{service-based architecture theo miền nghiệp vụ}; \textbf{event-driven processing} đóng vai trò bổ trợ cho các hệ quả nền như thông báo, cập nhật mô hình đọc báo cáo, kiểm toán và cảnh báo tồn kho. Cách lựa chọn này giữ tuyến giao dịch chính ngắn, đồng thời vẫn cho phép các hoạt động hỗ trợ được xử lý linh hoạt phía sau.

Từ các phương án trên, service-based architecture là cấu trúc chính vì bám sát các miền trách nhiệm đã nêu trong Chương~1. Event-driven processing không thay thế cấu trúc này mà bổ sung một cơ chế phối hợp cho các hệ quả không cần chặn thao tác của nhân viên. Sự kết hợp này tạo ra một kiến trúc vừa rõ ràng ở tuyến giao dịch chính, vừa đủ linh hoạt cho thông báo, báo cáo, kiểm toán và cảnh báo tồn kho.

\subsection{Hướng dẫn chạy project}\label{appendix:run-guide}

Phần hướng dẫn chạy cục bộ gồm các bước khởi động hệ thống trong phạm vi triển khai hiện tại. Các lệnh dưới đây bám theo cấu trúc \texttt{irms\_project}, cấu hình \texttt{docker-compose.yml}, Maven wrapper của backend và script frontend trong \texttt{package.json}.

\subsubsection*{Môi trường chạy cục bộ}

Môi trường chạy cục bộ của IRMS sử dụng Java 17 cho backend \textsf{Spring Boot}, Node.js/npm cho frontend React/TanStack Start, \textsf{Docker Compose} cho runtime container, \textsf{PostgreSQL} cho lưu trữ và \textsf{RabbitMQ} cho xử lý bất đồng bộ. Môi trường chạy cục bộ bằng Docker Compose được ghi nhận trong \adrref{ADR-0014}{adr:0014-docker-compose}. Khi chạy không qua Docker Compose, PostgreSQL cần sẵn sàng ở cấu hình local và RabbitMQ chỉ cần thiết khi bật broker-backed runtime thay vì chế độ local mặc định.

\subsubsection*{Cấu trúc thư mục liên quan}

\begin{itemize}
  \item \texttt{irms\_project/backend}: mã nguồn backend \textsf{Spring Boot}, Maven wrapper, Dockerfile, cấu hình \texttt{application*.properties} và migration Flyway.
  \item \texttt{irms\_project/frontend}: mã nguồn giao diện React/TanStack Start, cấu hình Vite/Nitro và Dockerfile frontend.
  \item \texttt{irms\_project/docker-compose.yml}: runtime container gồm PostgreSQL, RabbitMQ, migration, gateway, các service nghiệp vụ và frontend.
  \item \texttt{irms\_project/scripts}: script hỗ trợ chạy local trên Windows và Linux/macOS.
\end{itemize}

\subsubsection*{Khởi động bằng Docker Compose}

Cách chạy bằng Docker Compose phù hợp cho kiểm thử tích hợp và trình bày chức năng trong phạm vi học phần. Các thành phần chính có thể được khởi động từ thư mục \texttt{irms\_project} bằng các lệnh sau:

\begin{verbatim}
cd irms_project
docker compose config
docker compose build
docker compose up -d
\end{verbatim}

Compose khởi động \textsf{postgres}, \textsf{rabbitmq}, \textsf{irms-migration}, \textsf{api-gateway}, các service nghiệp vụ từ cổng 8081 đến 8088 và \textsf{frontend}. Theo cấu hình mặc định, giao diện nằm tại \texttt{http://localhost:5173}, gateway tại \texttt{http://localhost:8080}, RabbitMQ AMQP tại \texttt{localhost:5672} và giao diện quản trị RabbitMQ tại \texttt{http://localhost:15672}.

\subsubsection*{Chạy bằng script local}

Nếu chạy không qua Compose đầy đủ, project cung cấp script local để kiểm tra môi trường, biên dịch backend, chạy migration và khởi động các runtime cần thiết. Trên Windows có thể dùng:

\begin{verbatim}
cd irms_project
.\scripts\run-local.ps1
\end{verbatim}

Trên Linux/macOS có thể dùng:

\begin{verbatim}
cd irms_project
chmod +x scripts/run-local.sh
./scripts/run-local.sh
\end{verbatim}

Script local sử dụng \texttt{VITE\_API\_BASE\_URL=http://localhost:8080}, ghi log vào thư mục \texttt{.logs/local} và dùng PostgreSQL local với database \texttt{irms} khi cấu hình mặc định được giữ nguyên.

\subsubsection*{Chạy backend và frontend riêng}

Backend có thể chạy bằng Maven wrapper trong thư mục \texttt{irms\_project/backend}. Migration được chạy bằng profile \texttt{local,migration}; từng runtime service được chọn bằng profile \texttt{local,<service-name>}.

\begin{verbatim}
cd irms_project/backend
.\mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local,migration
.\mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local,api-gateway
\end{verbatim}

Các profile service tương ứng gồm \texttt{ordering-service}, \texttt{kitchen-service}, \texttt{billing-service}, \texttt{reservation-service}, \texttt{inventory-service}, \texttt{notification-service}, \texttt{reporting-service} và \texttt{identity-audit-service}. Trên Linux/macOS dùng \texttt{./mvnw} thay cho \texttt{.\textbackslash mvnw.cmd}.

Frontend chạy trong thư mục \texttt{irms\_project/frontend} bằng npm:

\begin{verbatim}
cd irms_project/frontend
npm install
$env:VITE_API_BASE_URL="http://localhost:8080"
npm run dev
\end{verbatim}

Trên Linux/macOS, biến môi trường có thể đặt cùng lệnh: \texttt{VITE\_API\_BASE\_URL=http://localhost:8080 npm run dev}. Cổng dev mặc định của Vite là \texttt{5173}.

\subsubsection*{Kiểm tra sau khi chạy}

Sau khi hệ thống khởi động, có thể kiểm tra giao diện tại \texttt{http://localhost:5173} và gateway tại \texttt{http://localhost:8080}. Endpoint health chuyên dụng được cấu hình ở \texttt{http://localhost:8080/api/health}; các service nội bộ trong Compose cũng dùng endpoint \texttt{/api/health} cho healthcheck của container.

\subsubsection*{Dữ liệu và migration}

Migration dùng Flyway trong backend và được bật ở profile/container migration trước khi các service nghiệp vụ chạy. Toàn bộ runtime hiện tại dùng một \textsf{PostgreSQL} vật lý duy nhất; các nhóm bảng giao dịch, \textsf{outbox\_events}, \textsf{processed\_events}, kiểm toán, định danh và read model báo cáo là các nhóm logic trong cùng PostgreSQL, không phải nhiều database vật lý riêng.
